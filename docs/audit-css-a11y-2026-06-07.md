# CSS + Accessibility Audit — 2026-06-07

Read-only audit of `static/main.css` (1715 lines, vanilla CSS) and the
`templates/` tree, against WCAG 2.2 AA and general maintainability
practice. Produced by four parallel scoped reviews: CSS architecture,
HTML semantics + ARIA, keyboard + focus, and color + motion. No code
was changed.

---

## Top findings — start here

If you only fix four things, fix these. Each is cross-cited below.

1. **Banner landmark is nested inside `<main>`** — header rendered from
   inside `{% block content %}`, so the `<header>` element never
   becomes a top-level `banner` landmark for AT. Fix in `base.html`
   structure. (HTML/ARIA → High)
2. **No skip-link** — keyboard and SR users must tab through site
   header + language switcher + bulletin strip + board controls
   (5–10 stops) before reaching the board on every page. (HTML/ARIA
   + Keyboard → High, two-finding overlap)
3. **`<tbody aria-live="polite">` on the board is too coarse** — every
   filter toggle, sort, status repaint, and flap-animation mutation
   becomes a polite announcement. Will over-announce on real ATs.
   (HTML/ARIA + Keyboard → Medium, two-finding overlap)
4. **Dead-rule pattern repeats** — `.weekly-grid-table` (typo of
   `.weekly-grid`), `.no-pools`/`.no-beaches` toggles with no CSS,
   21 `.fn-*` classes referenced by `templates/field-notes/*` with
   *zero* CSS and broken `<script>` srcs. The h2→h1 break we just
   fixed is one of a family. (CSS → High, three findings)

## Cross-cutting themes

- **Internationalization gaps in chrome surfaces.** Field-notes pages
  reimplement the header inline (no `chrome::site_header`), hardcode
  English `aria-label`s, and omit the language switcher entirely.
  Language switcher links carry no `lang`/`hreflang` so SR voices
  mispronounce them. (HTML/ARIA + Keyboard)
- **Selector-to-markup fragility.** Multiple rules rely on tag names
  (`.bulletin-hero h1`) or document order (`:nth-child(3n)` on the
  bulletin strip) where a class would survive markup edits. The
  recent regression is the canonical instance of this class of bug.
  (CSS)
- **Color-only signals on the map.** Marker color encodes status
  (red/ochre/teal/muted) and ochre fails 1.4.11 against most map
  tiles (~1.6:1). Status is only recoverable from the popup, which
  requires interaction. (Color + Motion)
- **`:focus` vs `:focus-visible` inconsistency.** Some buttons (filter
  pills) use the global `:focus-visible` outline; others (horizon
  menu, time banner, Leaflet, address actions) use plain `:focus` and
  apply a colored-fill hover treatment on any focus — including mouse
  click. (Keyboard)
- **Field Notes is published-but-broken.** Templates emit unstyled
  markup and reference JS files that don't exist (`js/field-notes.js`,
  `js/scrollspy.js` → 404). Either ship the feature or remove the
  templates. (CSS + HTML/ARIA)

## CSS Architecture & Selectors

### High

- **Issue**: `.weekly-grid-table` rule never matches — typo of `.weekly-grid`
  **Location**: `static/main.css:1591-1593`
  **Why it matters**: Mobile-only margin reset (`margin-left: 16px; margin-right: 16px`) targets `.weekly-grid-table`, but `templates/spots/page.html:391,444` emit `<table class="weekly-grid">`. The rule has been dead since the markup was renamed; phone margins on the schedule table currently come from `table.weekly-grid { margin: 0 28px }` at line 959 instead of the intended 16px override. Same failure mode as the recent `.bulletin-hero h2 → h1` regression.
  **Suggested fix**: Drop `.weekly-grid-table,` from the selector list — the existing `table.weekly-grid` selector below (or a new mobile override on it) is what fires.

- **Issue**: Dead `.no-pools` / `.no-beaches` class toggles with no CSS to act on
  **Location**: `static/js/filters.js:280-281` toggles classes on `table.board`; no rule in `static/main.css` references them.
  **Why it matters**: The JS comment at `filters.js:273-275` says "Hide either when its rows aren't visible so pool-only or beach-only views aren't padded with '—' placeholders." That hiding never happens — the columns are still rendered with `—`. Either the CSS was removed and the JS forgotten, or the CSS was never added.
  **Suggested fix**: Decide whether to ship the rule (e.g. `table.board.no-beaches [data-cell="water"] { display: none; }` plus matching `th:nth-child(4)` width tweak) or delete the two `classList.toggle` calls.

- **Issue**: Field Notes templates emit `.fn-*` classes with no CSS support at all
  **Location**: `templates/field-notes/index.html:30-92`, `templates/field-notes/page.html:25-71` (classes: `.fn-hero`, `.fn-eyebrow`, `.fn-hero-stamp`, `.fn-overview`, `.fn-swim-lane`, `.fn-lane-copy`, `.fn-lane-list`, `.fn-lane`, `.fn-lane-number`, `.fn-lane-rule`, `.fn-lane-cta`, `.fn-prose`, `.fn-lap-notes`, `.fn-lap-grid`, `.fn-lap-card`, `.fn-article`, `.fn-article-head`, `.fn-layout`, `.fn-toc`, `.fn-toc-label`, `.fn-toc-list`)
  **Why it matters**: 21 unique classes referenced by templates, zero rules in `main.css`. The pages render but get only browser defaults. Templates also reference `js/field-notes.js` and `js/scrollspy.js` (`field-notes/index.html:96`, `field-notes/page.html:75`) which don't exist in `static/js/` — those `<script>` tags 404.
  **Suggested fix**: Either land the missing CSS + JS, or remove the Field Notes templates / scripts blocks until the feature is shipped. Currently this is published-but-broken surface area.

### Medium

- **Issue**: `.view-switcher .view-switcher-link` rules have no callers
  **Location**: `static/main.css:444, 460, 1635`
  **Why it matters**: Searched every template and JS file — `view-switcher` only appears in a stale comment (`static/js/filters.js:41`). Three rule blocks (base styling, hover, and mobile min-height) maintained for nothing, and the comment misleads future readers into thinking it's live markup.
  **Suggested fix**: Delete all three rules and update/remove the `filters.js:41` comment.

- **Issue**: `.address` and `.official` in shared selector have no matching markup
  **Location**: `static/main.css:773-780`
  **Why it matters**: `.back, .address, .official { ... }` — only `.back` is emitted (`spots/page.html:213`). `.address` and `.official` don't exist in any template (`.address-actions` is distinct). The selector list is misleading and risks someone adding markup that "inherits" surprising padding.
  **Suggested fix**: Replace with `.back { ... }`.

- **Issue**: `.status-pill.is-info` modifier never applied
  **Location**: `static/main.css:663`
  **Why it matters**: Grepped templates + `static/js/status.js` — no code path sets `is-info`. The four other modifiers (`is-open`, `is-soon`, `is-ocean`, `is-closed`) are all used.
  **Suggested fix**: Remove, or document the contract (which status value should produce it) so it gets wired up.

- **Issue**: Meta-strip styling depends on stable `:nth-child` positions of `<div>` children
  **Location**: `static/main.css:289, 296-297, 1675-1677`; markup at `templates/index.html:51-58`, `templates/spots/page.html:204-209`, plus a different 6-cell layout at `templates/field-notes/index.html:19-26` and `field-notes/page.html:25-32`
  **Why it matters**: Border-right removal and row-break borders are computed from `:nth-child(3n)` / `:nth-child(n+4)` assuming six cells in a fixed order. Reordering, adding, or conditionally hiding any `<div>` inside `.bulletin-strip` silently breaks the responsive grid (orphaned borders, doubled rules). The Field Notes variants happen to also have six cells — that's load-bearing.
  **Suggested fix**: Either freeze the contract with a comment at the markup ("must be exactly six children, in this order") or switch to attribute-based selectors like `.bulletin-strip > div[data-edge="row"]`.

- **Issue**: Inline `style="--weekday-count: N"` in templates
  **Location**: `templates/spots/page.html:391, 444`
  **Why it matters**: These two are the only inline styles, and they're a legitimate use of custom properties for dynamic values. But the value is also set in CSS as `--weekday-count, 7` fallback (`main.css:957`), so the `style="--weekday-count: 7"` on line 444 is redundant.
  **Suggested fix**: Drop the redundant `style="--weekday-count: 7;"` on `page.html:444`. Keep the dynamic one on line 391.

- **Issue**: `.cost-badge` defined twice with conflicting expectations
  **Location**: `static/main.css:534-547` (component definition) and `static/main.css:631` (`margin-right: 8px; vertical-align: 0.1em;`)
  **Why it matters**: Line 631 lives inside the "Board table" section and adds layout properties globally, not scoped to the table. Any future use of `.cost-badge` outside the table (e.g., the spot detail meta strip at `spots/page.html:229` already uses it) inherits an 8px right margin you may not want.
  **Suggested fix**: Scope to the table: `table.board .cost-badge { margin-right: 8px; vertical-align: 0.1em; }`, or fold the spacing into the base `.cost-badge` rule deliberately.

- **Issue**: Tag-based selectors inside `.bulletin-hero h1` are fragile to markup tweaks
  **Location**: `static/main.css:207-220`
  **Why it matters**: This is the same pattern as the h2 → h1 regression you just fixed. `templates/index.html:64-67` wraps three `<span>` children inside the `<h1>`; if a designer adds a wrapping `<span>` or splits a word, `.bulletin-hero h1 span { display: inline-block }` cascades into nested spans. The hero is the highest-visibility surface — worth tightening.
  **Suggested fix**: Use direct child selector and explicit classes: `.bulletin-hero h1 > span` (already works), and consider `.hero-word` / `.hero-word--red` / `.hero-word--teal` if you want to be safe against future heading-tag changes.

### Low

- **Issue**: Mobile bottom-nav rules style nested elements via descendant chains
  **Location**: `static/main.css:1499-1549`
  **Why it matters**: `.site-header-actions` becomes a fixed footer-nav on phones, with five rules drilling into `.site-nav-link`, `.language-switcher`, `.language-switcher a`, `.language-switcher a[aria-current="page"]`. If a future change reuses `.site-header-actions` elsewhere, the phone rebrand leaks.
  **Suggested fix**: Add a 1-line comment at line 1499 noting that "the bottom-nav is `.site-header-actions` reflowed; do not reuse this class outside the header" — or rename the mobile pattern to a separate `.mobile-tabbar` toggled by JS / CSS.

- **Issue**: Naming inconsistency — three component prefix conventions in active use
  **Location**: throughout `static/main.css`
  **Why it matters**: `.site-*` (header), `.bulletin-*` (hero/strip), `.weekly-grid-*` (schedule), `.club-*` / `.cost-*` / `.status-*` (atoms), but also flat names (`.hero-line`, `.hero-stamp`, `.brand-dot`, `.row-arrow`, `.fallback`, `.deck`, `.eyebrow`, `.zone`, `.em`, `.k`, `.v`). The flat ones (`.em`, `.k`, `.v`, `.deck`, `.zone`, `.eyebrow`) collide easily across components.
  **Suggested fix**: Don't go BEM, but rename the shortest globals (`.em`, `.k`, `.v`) to scoped equivalents — e.g., `.bulletin-strip .key` / `.bulletin-strip .value` — since they only exist inside `.bulletin-strip`.

- **Issue**: Specificity hazard around `table.board tbody tr` and odd-row striping
  **Location**: `static/main.css:582-584` (desktop), `716-721` (mobile)
  **Why it matters**: Desktop sets odd-row background on `tr:nth-child(odd) td`; hover sets it on `tr:hover td`. Mobile overrides both on `tr` (not `td`) and then resets `td` backgrounds to transparent. The ordering works, but any new rule that touches `td` background inside `@media (max-width: 640px)` will be overridden without obvious cause.
  **Suggested fix**: Add a one-line comment at line 719-721 explaining the asymmetric `tr` vs `td` targeting.

- **Issue**: Two `@media (max-width: 640px)` blocks instead of one
  **Location**: `static/main.css:691-757` (table reflow) and `1471-1714` (everything else)
  **Why it matters**: Six total `@media` blocks — modest. But two share an identical breakpoint, separated by ~700 lines. Easy to add a phone rule in the wrong block.
  **Suggested fix**: Either merge them, or add a `/* phone — see also line 691 */` pointer at the top of the second block.

- **Issue**: `.detail-root`, `.club-list`, `.weekly-grid-session`, `.pricing-note`, `.fallback`, `.weekly-grid-head` exist in markup but have no rules
  **Location**: `templates/spots/page.html:277, 47, 426, 99, 479, 392`
  **Why it matters**: `.fallback` is user-facing copy shown on a schedule trust failure with no styling — it renders as a plain `<p>` inside `.detail-root`. The others are semantic hooks for future styling or unused.
  **Suggested fix**: Style `.fallback` deliberately, and delete the others from templates if they're not load-bearing JS hooks.

### Categories with no issues found

- **Inline `style` misuse**: only the two `--weekday-count` cases above, both legitimate dynamic values.
- **`!important` overuse**: `[hidden] { display: none !important; }` (canonical) and Leaflet overrides (unavoidable third-party). Nothing else.
- **True duplicate selectors**: none. `.cost-badge` is split across sections (above) but not duplicated.

## HTML Semantics & ARIA

### High

- **Issue**: Site banner and primary nav nested inside `<main>` (no `role="banner"` landmark)
  - **Location**: `templates/base.html:26-29`; site header rendered via `templates/macros/chrome.html:13-28` is called from `block content`, e.g. `templates/index.html:35,38`, `templates/spots/page.html:201`, `templates/field-notes/page.html:7-17`, `templates/field-notes/index.html:7-17`
  - **Why it matters**: WCAG 1.3.1 / ARIA Landmark practice: `<header>` becomes a `banner` landmark only when it is a top-level child of `<body>`. Here it is a descendant of `<main>`, so screen reader landmark menus get one `main` with everything inside it instead of separate `banner` + `main` + `contentinfo` regions. The footer is correctly outside `<main>`, but the header is not.
  - **Suggested fix**: In `base.html`, render the header outside `<main>`. Easiest path: add `{% block pre_main %}{% endblock %}` in `base.html` between `<body>` and `<main>`, move the `{{ chrome::site_header(...) }}` calls into that block.

- **Issue**: Map page `<h1>` is empty and visually hidden
  - **Location**: `templates/index.html:36`; built artifact `public/map/index.html` shows `<h1 class=sr-only></h1>` (empty content rendered)
  - **Why it matters**: WCAG 2.4.6 (Headings and Labels) and 1.3.1: an empty `<h1>` provides no accessible name and breaks the outline. The translation key `map_title` is not resolving for the default-language map page.
  - **Suggested fix**: Verify `trans(key='map_title', lang=lang)` resolves; if the key is missing in `i18n/ui/en.toml`, add it. Confirm by rebuilding and re-grepping `public/map/index.html`.

- **Issue**: No "skip to main content" link
  - **Location**: `templates/base.html:26-29` (no skip-link before `<main>`)
  - **Why it matters**: WCAG 2.4.1 (Bypass Blocks). Keyboard / switch users must tab through the site header, nav, and language switcher on every page before reaching the board content.
  - **Suggested fix**: Add `<a class="skip-link" href="#main">{{ trans(key='skip_to_content', lang=lang) }}</a>` as the first child of `<body>`, give `<main id="main" tabindex="-1">`, and style `.skip-link` with the standard "visually hidden until focus" pattern.

- **Issue**: Field-notes templates hardcode English `aria-label`s and duplicate the chrome header
  - **Location**: `templates/field-notes/index.html:7-17`, `templates/field-notes/page.html:7-17`
  - **Why it matters**: WCAG 3.1.2 (Language of Parts): `aria-label="View board"`, `"View map"`, `aria-label="On this page"`, `aria-label="Deep dives"`, `aria-label="Field notes"`, `aria-label="Field note"` are baked in English even on translated pages. Also, these files reimplement the site header inline instead of using `chrome::site_header(...)`, so they have drifted: they wrap the site title in an `<h1>` (page-level heading conflict — see next) and omit the `<nav class="language-switcher">` entirely.
  - **Suggested fix**: Replace the inline header in both files with `{{ chrome::site_header(...) }}` (add a `field-notes` branch in `chrome.html` if needed). Move all field-notes UI strings to `i18n/ui/*.toml`.

### Medium

- **Issue**: Field-notes pages use `<h1>` for the site title, demoting page titles to `<h2>` (multiple-h1 risk, broken outline)
  - **Location**: `templates/field-notes/index.html:9` (`<h1><a class="site-title">…</a></h1>`) and `:30` (`<h2>FIELD NOTES.</h2>`); `templates/field-notes/page.html:9` and `:38` (`<h2>{{ page.title }}</h2>`)
  - **Why it matters**: WCAG 2.4.6 + 1.3.1. The page's actual subject is "Field Notes" / the note title; making the wordmark the `<h1>` is purely stylistic. SR users navigating by heading hear "SWIM·FRANCISCO" on every page with no page-distinguishing label.
  - **Suggested fix**: Drop the `<h1>` wrapper from the site title. Promote `<h2>FIELD NOTES.</h2>` and `<h2>{{ page.title }}</h2>` to `<h1>`, then renumber the rest.

- **Issue**: Homepage table headers lack `scope="col"`
  - **Location**: `templates/index.html:122-130`
  - **Why it matters**: WCAG 1.3.1. The weekly grid (`templates/spots/page.html:394-399, 447-453`) sets `scope` correctly; the board doesn't, so the codebase is inconsistent.
  - **Suggested fix**: Add `scope="col"` to each `<th>` in the board `<thead>` row.

- **Issue**: `aria-live` region is too coarse — wraps the entire `<tbody>`
  - **Location**: `templates/index.html:131` (`<tbody aria-live="polite" aria-atomic="false">`)
  - **Why it matters**: WAI-ARIA APG: live regions should wrap the smallest element whose changes you actually want announced. Wrapping `<tbody>` means every filter toggle, sort, time-banner flap, and status repaint causes a flood of mutations the AT may try to read. `filters.js:284` triggers a split-flap animation on every visible row on every interaction; `status.js` repopulates STATUS/NEXT cells on a timer. This will over-announce.
  - **Suggested fix**: Either (a) remove `aria-live` from `<tbody>` and add a single small status region that summarizes "Showing N pools" after filter changes (the `sf:filters-applied` event already fires), or (b) restrict it to the STATUS pill cells. The existing `aria-live="polite"` on `.deck` (line 58) is appropriately sized.

- **Issue**: `.status-slab` on spot pages is `aria-live="polite"` but its content rarely changes
  - **Location**: `templates/spots/page.html:280`
  - **Why it matters**: Live regions announce mutations after page load. The status/next values are populated by JS once and updated on minute ticks, so SR users hear status repeatedly. Reserve live regions for genuinely transient updates.
  - **Suggested fix**: Drop `aria-live` from `<section class="status-slab">`.

- **Issue**: Language switcher links lack a discriminator beyond the locale label
  - **Location**: `templates/macros/chrome.html:21-25`
  - **Why it matters**: WCAG 3.1.2 (Language of Parts). Link text is the bare locale code (`EN`, `ES`, `中文`, `FIL`, `VI`, `FI`). Screen readers pronounce "FI" in the page's language, mangling Finnish.
  - **Suggested fix**: Render each as `<a href="..." hreflang="{{ locale.code }}" lang="{{ locale.code }}">{{ locale.label }}</a>` and consider adding `aria-label="{{ locale.full_name }}"`.

- **Issue**: "BULLETIN 05" issue number hidden from AT via `aria-hidden`
  - **Location**: `templates/macros/bulletin.html:1-8`
  - **Why it matters**: The issue number is content, not decoration. `aria-hidden="true"` removes it from the accessibility tree. The hero eyebrow on `index.html:52` exposes the label, but spot pages and field-notes render the badge with no alternate exposure.
  - **Suggested fix**: Either drop `aria-hidden="true"` and let it announce, or ensure the bulletin number is exposed elsewhere on every page that shows the badge.

- **Issue**: Filter `<button>` long `aria-label`s may shadow visible text
  - **Location**: `templates/index.html:90-105`; JS `static/js/filters.js:218-223, 304-389`; i18n keys `memberships_aria`, `sort_next_aria`, `sort_distance_aria`
  - **Why it matters**: When `aria-label` is set, the visible text is hidden from AT — SR users hear only the long label and never the short one. If the long label paraphrases the visible text, it's wasted; if it adds context, use `aria-describedby` instead so both are read.
  - **Suggested fix**: Audit `i18n/ui/en.toml`. If the visible text and the aria-label say roughly the same thing, drop the aria-label. If they differ, use `aria-describedby`.

- **Issue**: Horizon menu trigger declares `role="menu"` but children may not implement menu semantics
  - **Location**: `templates/index.html:78-83, 109`
  - **Why it matters**: `role="menu"` implies an application-style menu where children are `role="menuitem"` and arrow keys navigate. If items render as plain `<button>`s without `role="menuitem"`, the role is a lie — AT announces "menu" and then arrow keys behave inconsistently.
  - **Suggested fix**: Check `static/js/status.js` (which populates the menu). If items render as anchors / buttons rather than a true menu, switch to a disclosure pattern (no role on the panel, just `aria-expanded` on the button, `hidden` on the panel).

- **Issue**: Filter cluster uses `aria-label` instead of `aria-labelledby` despite having visible label text
  - **Location**: `templates/index.html:87, 89, 96, 101` and address-actions `templates/spots/page.html:237`
  - **Why it matters**: WAI-ARIA APG recommends `aria-labelledby` pointing at an existing visible label whenever one exists. The visible "Show:" / "Sort" / "When" labels and the AT label drift independently in translation files.
  - **Suggested fix**: Give each `.control-label` an id (e.g. `id="filters-label"`) and replace `aria-label="..."` with `aria-labelledby="filters-label"`.

### Low

- **Issue**: Spot page `<h1>` is split into multiple `<span>`s with an injected period
  - **Location**: `templates/spots/page.html:215-223`

- **Issue**: `.bulletin-strip` is a key/value list using `<div>` wrappers

- **Issue**: External links carry `target="_blank" rel="noopener"` but no AT warning

## Keyboard & Focus

### High

- **Issue**: No "skip to main content" link
  - **Location**: `templates/base.html:26-29` (also missing `id="main"` and `tabindex="-1"` on `<main>`)
  - **Why it matters**: Keyboard users tab through site header, language switcher, bulletin strip, board controls (5–6 filter buttons, sort buttons, horizon picker) on every page before reaching the table. WCAG 2.4.1 (Bypass Blocks). On mobile the sticky header + sticky `.board-controls` keep header focus pinned. *(Same finding as HTML/ARIA — counted once.)*
  - **Suggested fix**: First child of `<body>`: `<a class="skip-link" href="#main">Skip to main content</a>`. Give `<main id="main" tabindex="-1">`.

- **Issue**: Mobile bottom navigation appears at end of tab order, far from where it sits visually
  - **Location**: `templates/macros/chrome.html:17-26` + `static/main.css:1499-1549` — `.site-header-actions` is rendered inside `.site-header` at the top of the DOM, but `position: fixed` to `bottom: 0` on mobile.
  - **Why it matters**: On mobile, tab order lands on BOARD/MAP/language links immediately after `.site-title`, but those controls are visually pinned to the bottom of the viewport. Keyboard users get a focus indicator outside their viewport. WCAG 2.4.3 (Focus Order) and 2.4.11 (Focus Not Obscured).
  - **Suggested fix**: Either move the nav to the end of `<body>` and use CSS ordering on desktop, or on focus, scroll the element into view. Easiest: add `scroll-margin-bottom: 60px` to the nav links.

- **Issue**: Sticky board-controls and sticky header can obscure focused content scrolling under them
  - **Location**: `static/main.css:1483-1488` (sticky `.site-header`, `top:0`), `1594-1608` (sticky `.board-controls`, `top:56px`), plus fixed mobile nav at `bottom:0`. No `scroll-padding-top` / `scroll-padding-bottom` on `html`.
  - **Why it matters**: When tabbing through table rows, the browser scrolls the focused row into view but the sticky controls (~110 px tall combined on mobile) and fixed bottom nav (~58 px) overlap it. WCAG 2.4.11 (Focus Not Obscured Minimum, AA 2.2).
  - **Suggested fix**: `html { scroll-padding-top: 120px; scroll-padding-bottom: 70px; }` (or media-query specific values).

- **Issue**: Clickable rows are not keyboard-activatable as rows
  - **Location**: `templates/index.html:134-181` (`<tr data-slug="…">` with `cursor: pointer` and click handler in `static/js/expand.js:6-28`); CSS `static/main.css:585` adds `cursor: pointer` to all `<tr>`.
  - **Why it matters**: The whole row is mouse-clickable but the `<tr>` has no `role`, no `tabindex`, no `keydown` handler. Keyboard users can only activate the nested `<a>` in the SPOT cell. Strictly not a hard failure (the link works) but the affordance gap is real.
  - **Suggested fix**: Either (a) remove `cursor: pointer` on `<tr>` and rely on the cell anchor (simplest — and you can remove the expand.js click handler entirely), or (b) expand the anchor to fill the row using `td { position: relative }` + a `::before` overlay so the whole row is one large hit target with one focus stop.

### Medium

- **Issue**: `a:hover, a:focus` underline rule fires on mouse focus too
  - **Location**: `static/main.css:72` — `a:hover, a:focus { text-decoration: underline; … }`
  - **Why it matters**: Using `:focus` (not `:focus-visible`) means clicking a link triggers a persistent underline that resembles a focus state when no keyboard focus is intended. Inconsistent with the well-formed `:focus-visible` outline at lines 73-77.
  - **Suggested fix**: Replace `:focus` with `:focus-visible` on line 72, or remove the focus selector altogether since the 3px red outline already signals focus.

- **Issue**: Horizon picker, time-banner, leaflet zoom focus styles use plain `:focus` not `:focus-visible`
  - **Location**: `static/main.css:338-344`, `527-531`, `1425`, `875`
  - **Why it matters**: These apply hover styling (ink background, paper text) on any focus, including mouse-click. Not a contrast issue; inconsistent with the global `:focus-visible` outline.
  - **Suggested fix**: Promote to `:focus-visible` to limit colored-fill treatment to keyboard focus.

- **Issue**: Horizon menu does not trap focus or include `aria-activedescendant`; Tab leaks out of the open menu
  - **Location**: `static/js/status.js:381-450` — listeners handle ArrowUp/Down/Home/End/Enter/Space/Escape, but Tab is not intercepted.
  - **Why it matters**: ARIA APG for `role="menu"` expects Tab to close the menu and move focus to the next element after the trigger. Currently Tab moves focus into the page body while the menu remains visible.
  - **Suggested fix**: Listen for `focusout` on the menu container and close it when `relatedTarget` is outside both the menu and its button. Or close on Tab keydown explicitly. (Or switch to a disclosure pattern — see HTML/ARIA section.)

- **Issue**: Two live regions update simultaneously and rapidly when horizon changes
  - **Location**: `templates/index.html:58` (`.deck`) and `templates/index.html:131` (`<tbody>`). Horizon menu (`static/js/status.js:343-349`) calls `renderBoard()` + `applyBulletinStrip()` on every selection. *(Same root as HTML/ARIA `<tbody>` finding.)*
  - **Why it matters**: Switching among 7 horizon options queues 7×(deck + every status pill + open-count) polite announcements. Screen readers can spend 30+ seconds catching up. WCAG 4.1.3 (Status Messages).
  - **Suggested fix**: Debounce the deck announcement (250 ms after last horizon change), and demote the `<tbody>` from `aria-live` to a single visually-hidden `<div role="status">` summary.

- **Issue**: Map popups: focus is not returned to the marker on close
  - **Location**: `static/js/map.js:151-162` — markers + popup binding. No custom keyboard wiring.
  - **Why it matters**: Leaflet markers receive focus via Tab and Enter/Space opens the popup. However, after closing with Esc or `×`, Leaflet returns focus to `<body>` rather than the originating marker. WCAG 2.4.3 (Focus Order).
  - **Suggested fix**: On `marker.on("popupopen", e => …)` move focus into the popup; on `popupclose` call `marker.getElement()?.focus()` to return focus.

- **Issue**: Pressed filter button focus ring (red on red) collapses
  - **Location**: `static/main.css:73-77` (global outline) interacting with `464-468` (active filter button = red fill, red border).
  - **Why it matters**: When a pressed filter button is focused, the 3 px red outline at 3 px offset merges into the button border. WCAG 2.4.7 (Focus Visible) and 2.4.11.
  - **Suggested fix**: Dual-tone focus ring on pressed buttons, e.g. `outline: 3px solid var(--paper); box-shadow: 0 0 0 5px var(--ink);`, or switch focus color to `var(--ink)` when `[aria-pressed="true"]`.

### Low

- **Issue**: `cursor: pointer` on `<tr>` even when JS is disabled
  - **Location**: `static/main.css:585`
  - **Why it matters**: With JS disabled, the row click handler never attaches, but `cursor: pointer` still appears. Cosmetic.
  - **Suggested fix**: Move `cursor: pointer` to a class added by `expand.js` after init.

- **Issue**: Reduced-motion only covers the flap animation

  - **Location**: `static/js/filters.js:331-345`
  - **Why it matters**: SR users hear "ALL, pressed" as the default. Acceptable but a `role="radiogroup"` + `aria-checked` would be more precise.

## Color, Contrast & Motion

Light-theme only — no `prefers-color-scheme: dark` block exists in `static/main.css`, so dark-theme parity is N/A.

### High

- **Issue**: Filter chip ring border is mostly invisible against the controls strip
  - **Location**: `static/main.css:564` (`table.board td:not(:last-child)` border `rgba(26,24,18,0.22)`), `67-68` (`main` border `rgba(26,24,18,0.10)`)
  - **Measurement**: inner table column rule ≈`#c2b9a5` on paper = **1.57:1**; main side rules ≈`#dcd1bc` on paper = **1.22:1**
  - **Why it matters**: WCAG 1.4.11 (Non-text Contrast, AA 3:1). The 22%-ink column rules are the only thing separating SPOT / STATUS / NEXT / WATER / LOCALE; below 1.6:1 they read as decorative noise for low-vision users.
  - **Suggested fix**: Bump column rule to `rgba(26,24,18,0.55)` (~3.05:1), or `#8a7a52` (3.07:1 on paper). Faint `main` 0.10 rules are decorative.

- **Issue**: `--rule` (`#c8b88e`) used as a structural border fails non-text contrast everywhere
  - **Location**: `static/main.css:280` (`.bulletin-strip > div` right rule), `367` (`.horizon-menu button` bottom rule), `623` (`.locale-text` top rule), `657` (`.status-pill` border), `909` (`.today-block` top rule), `972-973` (weekly-grid cell borders), `1396` (Leaflet popup row rule), `1433` (attribution border)
  - **Measurement**: `--rule` on `--paper` = **1.58:1**, on `--paper-2` = **1.50:1**, on `--foam` = **1.74:1** — all fail AA 3:1
  - **Why it matters**: `--rule` is the dividing line for many grid cells, the closed status-pill border (the only thing differentiating a closed pill from background text since the fill is `--paper-2`), and weekly-grid hour cells.
  - **Suggested fix**: Darken `--rule` to `#9a8956` (3.06:1) or `#8a7a52` (3.07:1). Keep current shade as a decorative `--rule-soft`. For `.status-pill.is-closed`, switch border to `var(--muted)` (6.08:1).

- **Issue**: Ochre `.em` highlight has 2.00:1 fill contrast against paper, can be lost in print/forced-colors
  - **Location**: `static/main.css:230-234` (`.bulletin-hero .deck .em`)
  - **Measurement**: ochre block on paper = **2.00:1**; ink-on-ochre text inside = 7.18:1 (text itself passes)
  - **Why it matters**: WCAG 1.4.11 applies to graphical objects required to understand content. The yellow swatch on cream marks "5", "62°F", "58°F" as the live values. WCAG 1.4.1: the highlight is the only signal that those numbers are dynamic.
  - **Suggested fix**: Add a 1.5px ink border or 2px ink underline: `border-bottom: 2px solid var(--ink);` so the cue survives without the fill.

- **Issue**: Ochre dot markers on the bay are nearly invisible
  - **Location**: `static/main.css:1356` (`.sf-marker-soon .sf-marker-dot { background: var(--ochre); }`)
  - **Measurement**: ochre on water (CartoDB tile ≈`#bcd4dd`) = **1.60:1**, on park green (≈`#cde2c4`) = **1.80:1**, on cream tile = 2.11:1 — all fail 3:1
  - **Why it matters**: Markers carry status semantics (red=open, ochre=soon, teal=open_water, muted=other). The `--ink` 2px ring saves the marker from being lost, but the *color-coded meaning* fails. WCAG 1.4.1 (color-only signal) + 1.4.11.
  - **Suggested fix**: Either encode status in marker shape (square for "soon", diamond for "open_water"), add a small label/letter glyph inside each marker (O/S/B), or darken `--ochre` to ~`#a67817` (3.05:1 on water) for the marker variant only.

### Medium

- **Issue**: `--red` text on `--paper-2` lands exactly at AA threshold
  - **Location**: `static/main.css:1057` (`.closure-banner-date`), `1111` (`.pricing-price`)
  - **Measurement**: red on paper-2 = **4.50:1** (passes by 0 decimal margin); red on paper = 4.76:1
  - **Why it matters**: WCAG 1.4.3. Rounds-to-pass but brittle against tonal drift and small font sizes (`.pricing-list dt` is 11px) where you want headroom.
  - **Suggested fix**: Darken `--red` to `#a8311f` (5.16:1 on paper-2) — keeps the riso warmth, gives ~15% AA headroom.

- **Issue**: No `prefers-reduced-motion` reset for non-table animations
  - **Location**: `static/main.css:768-770` only disables `table.board tbody tr.flap`. Other motion uncovered: `333` (`.horizon-button::after` 120ms), `456` (filter buttons 120ms), `static/js/map.js:158` (`flyTo` 600ms).
  - **Why it matters**: WCAG 2.3.3. The 600 ms `flyTo` is a true animation and should be skipped under reduced-motion.
  - **Suggested fix**: In `map.js`, branch on `window.matchMedia("(prefers-reduced-motion: reduce)").matches` → `setView(...)` instead of `flyTo`. Add a catch-all:
    ```css
    @media (prefers-reduced-motion: reduce) {
      *, *::before, *::after { transition-duration: 0.01ms !important; animation-duration: 0.01ms !important; }
    }
    ```

- **Issue**: Smallest text in the bulletin strip drops to 9.5px on phones
  - **Location**: `static/main.css:1682` (`.bulletin-strip > div { font-size: 9.5px; white-space: nowrap; }`), `1430` (Leaflet attribution 9px), `1649` (filter buttons 9px on phones)
  - **Measurement**: 9–9.5px (below 10–11px label floor)
  - **Why it matters**: WCAG 1.4.4 (Resize text). Inside `overflow-x: auto` containers with `white-space: nowrap`, so 200% zoom scrolls horizontally rather than reflowing (also tests 1.4.10 Reflow).
  - **Suggested fix**: Raise `.bulletin-strip > div` mobile size to 10.5px, drop `letter-spacing` to `0.10em` to recover horizontal budget; allow the strip to wrap rather than `overflow-x: auto`.

- **Issue**: `--senior` token reads at the WCAG floor when used as label text on paper
  - **Location**: `static/main.css:30` (token), used at `1001` (`.weekly-grid-row[data-program="senior_swim"] .weekly-grid-rowlabel`)
  - **Measurement**: senior text on paper = **6.07:1** (passes); paper on senior = 6.07:1 (passes). No regression.
  - **Why it matters**: Forward-looking. Prevent the next "darken one token for one usage" patch.
  - **Suggested fix**: Document in `NAPKIN.md` or a CSS comment near `--senior` that this token is calibrated for ~6:1 and not for use on backgrounds darker than `--paper-2`.
